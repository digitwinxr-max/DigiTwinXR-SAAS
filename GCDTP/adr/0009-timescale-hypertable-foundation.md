# ADR-0009: TimescaleDB Hypertable Foundation

## Status

Accepted

## Context

GCDTP measurements are time-series data generated by sensors. As the system scales, we need to handle:
- Increasing volume of measurements
- Faster query performance for time-ordered data
- Efficient storage for historical data
- Retention policies for old data

Standard PostgreSQL tables struggle with large time-series datasets due to:
- No automatic partitioning
- Poor performance with millions of rows
- No built-in time-based optimization
- Manual maintenance for data retention

## Decision

We will convert the measurements table to a TimescaleDB hypertable:

1. **Enable TimescaleDB extension** - TimescaleDB is a PostgreSQL extension
2. **Convert to hypertable** - Use `timestamp` column as time dimension
3. **Optimize indexes** - Add indexes optimized for time-series queries
4. **Enable compression** - Compress old chunks automatically
5. **No API changes** - Existing endpoints remain unchanged

## Migration Details

### Database Migration

```sql
-- Enable TimescaleDB extension
CREATE EXTENSION IF NOT EXISTS timescaledb CASCADE;

-- Convert measurements table to hypertable
SELECT create_hypertable('measurements', 'timestamp',
    chunk_time_interval => INTERVAL '1 day',
    if_not_exists => TRUE
);

-- Optimized indexes for time-series queries
CREATE INDEX idx_measurements_sensor_time
    ON measurements (sensor_id, timestamp DESC);
CREATE INDEX idx_measurements_time_desc
    ON measurements (timestamp DESC);

-- Enable compression for old chunks
SELECT add_compression_policy('measurements', INTERVAL '7 days');
```

### Hypertable Architecture

TimescaleDB automatically partitions the measurements table into **chunks** based on time intervals:

```
measurements (hypertable)
├── measurements_1 (chunk: 2026-01-01 to 2026-01-02)
├── measurements_2 (chunk: 2026-01-02 to 2026-01-03)
├── measurements_3 (chunk: 2026-01-03 to 2026-01-04)
└── ...
```

Each chunk contains measurements for a specific time range, enabling:
- **Parallel queries** - Query multiple chunks simultaneously
- **Efficient pruning** - Skip irrelevant chunks for time-range queries
- **Compression** - Compress old chunks to save storage

| Aspect | PostgreSQL | TimescaleDB |
|--------|-----------|-------------|
| Partitioning | Manual | Automatic |
| Query Performance | Degrades | Constant time |
| Storage | Large | Compressed |
| Scaling | Limited | Horizontal-ready |

### Compatibility

TimescaleDB is **100% PostgreSQL compatible**:
- Same SQL syntax
- Same data types
- Same drivers (psycopg2)
- Same ORM (SQLAlchemy)
- Drop-in replacement

## Hypertable Benefits

### 1. Query Performance

TimescaleDB automatically uses **chunk exclusion** to skip irrelevant data:

```sql
-- This query only scans recent chunks
SELECT * FROM measurements 
WHERE timestamp > NOW() - INTERVAL '1 day';
```

The hypertable indexes complement chunk exclusion:
- `idx_measurements_sensor_time` - Fast sensor-specific queries
- `idx_measurements_time_desc` - Fast time-ordered scans

### 2. Compression

Old chunks can be compressed automatically:

- **Before compression**: ~100 MB/day of raw data
- **After compression**: ~10 MB/day (90% reduction)
- Compression runs automatically on background workers

### 3. Retention Policies

Old data can be dropped automatically:

```sql
-- Drop chunks older than 90 days
SELECT add_retention_policy('measurements', INTERVAL '90 days');
```

### 4. Scalability

TimescaleDB is designed for:
- **Millions of sensors** - Scales horizontally
- **Billions of measurements** - Time-based partitioning
- **High ingestion rates** - Up to millions of inserts/second

## Migration Strategy

### Zero-Downtime Migration

1. **Backup** - Create database backup
2. **Add extension** - `CREATE EXTENSION timescaledb`
3. **Convert** - `SELECT create_hypertable(...)` - no data copy
4. **Verify** - Run existing tests
5. **Deploy** - Update docker-compose for TimescaleDB image

### Data Preservation

- No data migration required
- `create_hypertable` converts existing data
- All existing measurements preserved
- All indexes created for existing data
